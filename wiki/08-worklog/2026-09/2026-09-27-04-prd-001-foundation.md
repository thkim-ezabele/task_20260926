## 주요 프롬프트

1. `/prd` "이제 위키 구축은 마무리 하고 실제 프로젝트 구현 시작을 위한 아키텍쳐 설계를 진행하려고해 … 인프라 설계부터 .net8 프로젝트 기본 설계까지만 진행하는 요구사항을 설계하는게 목표야"
2. "각 항목 선택지 비교하고 추천해줘" (미정 기술 선택 9개)
3. "1. 현재 도입하지 않음 2. 현재 도입하지 않음 대신 aspire 솔루션형태로 코드 생성 3. 현재 도임하지 않음 4. 직접구현 5. controller 나머지는 추천안해로 진행"
4. "좋아 그대로 리뷰 진행해줘" → 차단 질문 답변 → "승인"

## 작업 내용

- **⓪ 사전 점검**: 작업 트리 깨끗(raw 로그만 변경), `develop`, 진행 중 토픽 없음 → PRD-001, S01부터.
- **① 인터뷰**: 산출물(설계 + 뼈대 코드), 인프라 범위(로컬만), 솔루션 범위(BuildingBlocks + Employee 샘플), CI 포함을 정했다. 미정 기술 9개(브로커, Gateway, 로그 수집기, Mediator, API 스타일, DI 타입 검색, UUID v7, 단언, 결정 시점)는 선택지 비교표와 추천을 제시하고 답을 받았다. 이어서 Aspire 사용 방식(AppHost만, docker compose 없음), Aspire 9.x + .NET 8 SDK, 샘플 서비스 Employee를 정했다.
- **② PRD 초안**: `PRD-001-foundation.md` 작성(FR 11, NFR 7) → 사용자 확인.
- **③ 병렬 리뷰**: orchestrator ∥ dba ∥ developer. 세 리뷰가 공통으로 지적한 문제: Aspire가 주는 연결 문자열 하나와 ADR 0009의 Write / Read 분리가 맞지 않음, 마이그레이션 적용 주체가 없음, Aspire 재시도 실행 전략과 트랜잭션 직접 호출이 충돌함.
- **④ 통합**: orchestrator가 차단 질문 3건(BQ1~BQ3)과 비차단 기본값을 정리 → 사용자 답변 → PRD에 반영(Q8~Q19, 리뷰 요약 표).
- **⑤ 스프린트 분할**: 4개 스프린트, 22개 작업으로 분할했다. 작업마다 단계별 역할(dba / developer / reviewer / tester)과 tester 검증 기준을 적었다. 미결 운영 메모는 N1~N3 세 건이다.
- **⑥ 승인 → ⑦ 반영**: `feature/prd-001-foundation` 브랜치를 만들었다. 스프린트 문서 4개 작성, PRD `stable`, 개발 관리 목록 · 로드맵 갱신 후 커밋 · push했다. Draft PR #7을 만들고 PR 번호를 기록한 뒤 다시 커밋 · push했다.

## 이슈 / 배운 점

- `/prd` 첫 운영에서 리뷰가 실제로 설계 공백을 잡았다. Aspire 연결 주입과 ADR 0009 Write / Read 분리의 불일치, 재시도 실행 전략과 트랜잭션 충돌이 그 예다. 인터뷰만으로는 드러나지 않던 문제였다.
- 첫 AskUserQuestion(미정 기술 선택)에서 사용자가 선택지 비교를 먼저 요청했다. 기술 선택처럼 판단 근거가 필요한 질문은 비교표를 먼저 보여 주고 묻는 편이 낫다.
- 운영 흐름의 빈틈 3건을 스프린트 문서 계획 리뷰 절에 메모로 남겼다.
  - N1 (S01): `/sprint` 파이프라인에 ADR 사용자 확인 단계가 없음
  - N2 (S04): CI 실패 확인용 임시 브랜치 push가 "push는 스프린트 종료 때만" 규칙과 충돌
  - N3 (S02): 공통 API 처리를 둘 BuildingBlocks 프로젝트가 없음
- 확인하지 못한 것: 고정할 Aspire 9.x 마이너 버전이 net8.0 AppHost를 지원하는지, 패치를 받는지(S01-T01에서 확인). .NET 8 지원 종료(2026-11-10)가 토픽 진행 중에 온다.
